 Challenge Title: DashMart Search & Recommendations Re-Ranking EngineBusiness ContextWhen a user searches for items in DashMart (e.g., "snack" or "beverage"), the baseline retrieval system fetches candidate items. As part of the Search & Recommendation team, your task is to build a modular, production-ready Re-Ranking Engine that scores, filters, and re-orders candidate items in real time based on user intent, business margin, and strict hard constraints.  Candidate Data SchemaYou will be provided with a dictionary / list of candidate items, where each item has the following attributes:item_id (str): Unique identifier for the item.title (str): Name of the product (e.g., "Organic Potato Chips 8oz").category (str): Primary category (e.g., "Snacks", "Beverages").brand (str): Item brand (e.g., "Lays", "Doritos").base_price (float): Retail price in USD.margin_rate (float): Profit margin percentage (e.g., 0.25 for 25%).pctr (float): Predicted Click-Through Rate ($0.0 \le \text{pCTR} \le 1.0$).in_stock (bool): Current availability status at the local DashMart fulfillment center.Core Requirements (To implement in Python)Your solution should be structured as a clean Python module (e.g., in main.py):  Hard Filtering (Guardrails)Filter out any items where in_stock == False or base_price <= 0.Handle missing values or NaNs gracefully without crashing.Multi-Factor Scoring FunctionCompute a composite_score for each valid item using a weighted linear combination:$$\text{Score} = w_1 \cdot \text{pCTR} + w_2 \cdot (\text{base\_price} \times \text{margin\_rate}) + w_3 \cdot \text{Relevance}$$Relevance Calculation: Perform a simple keyword-matching relevance score between the search query and title (e.g., exact/partial string match ratio).Diversity & Deduplication Filter (Business Rules)Sort items by composite_score in descending order.Apply a Brand Diversity Constraint: To prevent a poor user experience, no more than 2 consecutive items in the top-$K$ output can belong to the same brand. If a 3rd consecutive item has the same brand, skip it and push it lower down the queue.Unit Testing & Edge Case ValidationWrite lightweight unit tests (using assert or pytest) to verify:  Out-of-stock items are correctly excluded.  The brand diversity constraint is strictly enforced.  Handling of empty candidate lists or empty search queries.
